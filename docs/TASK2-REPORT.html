1. Result

The method works from the deployed file only. It runs in the Linux VM of the Claude desktop app, on your Mac. It needs no terminal, no CLI and no network. The decompiled code did not go to the cloud for the decompile step.

Use CFR as the primary decompiler. Use JADX only to look up parameter names of interface methods.

Method bodies: 4 sample classes

I compared PetValidator, OwnerController (Boot), CallMonitoringAspect and JdbcOwnerRepositoryImpl (WAR) line by line after I removed comments. All CFR method bodies have the same behavior as the source. Only the form changes:

Source
this.jdbcClient.sql("""
    SELECT id, first_name, ...
    FROM owners
    WHERE last_name like :lastName
    """)
  .param("lastName", lastName + "%")
CFR
this.jdbcClient.sql("SELECT id, first_name, ...\nFROM owners\nWHERE last_name like :lastName\n")
  .param("lastName", (Object)(lastName + "%"))

7. For your real WAR and JAR files

  1. Put the file in a connected folder on the work computer (for example SkillsPlugins/real/).
  2. Copy tools/ and decompile-java-artifact.sh to that computer. The VM there probably cannot download them.
  3. Ask Claude (desktop app, this Project) to run the script in the VM.
  4. Look first at: src/main/resources (secrets from filtering), _meta/MANIFEST.MF, _meta/git.properties (exact commit), DEPENDENCIES.md (CVE check).
  5. For Spring Boot 3.3+ JARs, the SBOM gives exact library coordinates. For WAR files, expect gaps in the group IDs.
Decision (2026-10-15). Decompiled code of your real files can go to Claude desktop chat and Anthropic. Claude can read the output and write COMPONENTS.md. The real file and the decompile run stay on your computer.
